## Fix (follow-up): Thai word-segmentation fix from earlier was itself producing garbled output (real user screenshot after deploy)
The GPT-based regroup shipped earlier (`prompts/word-segment.ts` + a first version of `lib/media/word-segment.ts`) was live-tested by the user and made things worse in places — the Live Editor timeline showed nonsensical fragments like "แยนท" / "งขายก" / "ีดส" that don't correspond to real Thai syllables at all, and the burned-in caption overlay showed the same garbling ("ีดสุดยึดสุดจ..."). - [x] **Replaced the AI approach with a purely deterministic, rule-based repair** — `lib/media/word-segment.ts` rewritten from scratch (`repairThaiTokenFragments`): (1) a Whisper token that is *nothing but* a bare leading vowel (เ แ โ ใ ไ) is always a fragment — Thai leading vowels are written before the consonant they're pronounced after, so it's merged forward into the next token; (2) a token that *starts with* a non-spacing combining mark (tone marks, above/below vowels) or one of the two spacing marks that always attach to the preceding consonant (ะ, ำ) can never legitimately start a token — merged backward into the previous token. - [x] **Honest limitation, disclosed rather than hidden**: this is a real downgrade in ambition from "fully merge into real dictionary words" to "guarantee no orthographically-invalid fragment" — Whisper's native token granularity for Thai is often at the syllable level, so Live Editor timeline blocks may still show syllables rather than full words in many spots (e.g. "การ" + "ทำ" + "งาน" as 3 blocks instead of 1).
